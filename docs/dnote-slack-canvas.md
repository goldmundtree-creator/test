# dNote 슬랙 활용 가이드 (Canvas)

> #dnote 채널 대화를 분석해 정리한 슬랙 활용 개선안입니다. 팀 공유용으로 채널 상단에 고정해 사용하세요.

---

## 현재 채널 사용 패턴

지금 **#dnote** 채널은 여러 성격의 메시지가 한곳에 섞여 있습니다. 인사말, 자동 이슈 리포트(문제보고), AI 주간 프로젝트 요약, 외부 기사 공유, 원장 아이디어, 개발 관련 질문(API 등)이 구분 없이 흐르고 있습니다.

4인 팀에서는 단일 채널이 편할 수 있지만, 메시지 종류가 늘면 **중요한 VOC나 위험 항목이 묻히기 쉽습니다.**

---

## 개선 제안

### 1. 채널 분리 (가장 큰 효과)

성격별로 채널을 나누는 것을 권합니다.

| 채널 | 용도 |
| --- | --- |
| `#dnote-voc` | 고객 불만 / 버그 리포트 전용 (오복어린이치과 요약 분량 이슈, 오스템 잘못된 요금 안내 같은 항목이 묻히지 않게) |
| `#dnote-영업` | 콜드콜 · 인터뷰 · 제휴 진행 상황 |
| `#dnote-개발` | API 질문, 자동화 워크플로우, 모델 라우팅 같은 기술 논의 |
| `#dnote` | 전사 공지 · 주간요약 · 아이디어 공유만 남기기 |

> 채널이 너무 많으면 오히려 부담이니, 최소 `#dnote-voc`만이라도 분리하면 위험 항목 추적이 크게 좋아집니다.

### 2. 자동 이슈 리포트에 담당자 · 상태 워크플로우 추가

지금은 "문제보고 테스트"처럼 이슈가 들어오면 그냥 메시지로 끝납니다. Slack 워크플로우로 이슈 접수 시 자동으로 담당자 멘션 + 상태 이모지 컨벤션을 붙이면 미해결 VOC를 한눈에 볼 수 있습니다.

- :white_check_mark: 완료
- :eyes: 처리중

> 주간요약의 위험 3건(오복 VOC, 서티라이프 요금 오안내, 업무폰 이동)이 좋은 예입니다 — 해결될 때까지 추적되어야 합니다.

### 3. 주간 요약을 실제 액션 아이템으로 연결

AI 주간 요약이 잘 만들어지고 있는데, "우선순위 상" 항목들이 다음 주에 실제로 처리됐는지 확인하는 고리가 없습니다.

- 요약에서 나온 우선순위 항목을 각 담당자가 :white_check_mark: 로 마킹
- 또는 별도 스레드에서 후속 보고하는 루틴 운영

### 4. 멘션과 스레드 활용

특정인에게 답을 원하는 메시지(원장 아이디어, API 질문 등)는 잘 멘션하고 있습니다. 다만 답변이 새 메시지로 오면 맥락이 끊기니, **답변은 항상 스레드로 다는 컨벤션**을 정하면 채널이 훨씬 깔끔해집니다.

### 5. 채널 북마크 / 캔버스 활용

다음 정보를 채널 상단 북마크나 Canvas에 고정해두면 반복 실수를 막을 수 있습니다.

- dNote 매뉴얼
- 자주 쓰는 링크
- 현재 가격 정책 (29,800원 / 10,000P)
- 파트너사 안내 정정 정보

> 서티라이프 요금 오안내 같은 실수가 반복되지 않습니다.
